# Surface: terces GitHub Pages site (site/index.html)

Mode: Persuade. Audience: platform and security engineers who evaluate a self-hosted secret scanner for their GitHub orgs. Action: run the quick start, open the example report, read the docs on GitHub. Proof: real CLI output, a real HTML report, measured benchmark, all from synthetic tokens. Constraints: static HTML, CSS and minimal vanilla JS in site/, no external requests, no full token-shaped string in the source, STE copy, no invented users or claims.

## Direction contract

THESIS: Follow one leaked token through terces, from the commit to a stored fingerprint. The page refuses the category default of a hero slogan over a feature-card grid.

OWN-WORLD: The incumbent report world: ground #f7f7f5, white panels with 1px #e2e2dc rules and 10px corners, ink #1d1d1b, accent #2f5d50, severity pills in #a4161a, #c2410c, #b08900, #5c7080, ui-monospace for every artifact, system sans for prose, dark mode from the same tokens.

STORY: The visitor sees a token enter a commit, sees terces catch it in a pull request, sees it become a fingerprint and a preview, sees the report, then runs the quick start.

FIRST VIEWPORT: Left half: headline and one-line offer, install command, two actions. Right half: a commit diff panel that adds a fake token generated in the browser, and under it the stored row with preview and live HMAC fingerprint. A button makes a new fake token and the fingerprint changes.

FORM: Structure 4 of 7 on the ranked list, dealt as the lead. Seed key d438c66f. Signature interaction: the live token-to-fingerprint panel, plus a step rail that tracks the journey on scroll.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
